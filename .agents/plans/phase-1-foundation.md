### Patterns to Follow

**Naming Conventions:**
- Components: PascalCase (`Nav.tsx`, `Footer.tsx`)
- Files in `app/`: lowercase (`layout.tsx`, `page.tsx`, `globals.css`)
- CSS classes: Tailwind utility classes, NO custom CSS classes unless absolutely needed
- Import alias: `@/*` mapping to project root

**Component Pattern:**
- All components are React Server Components by default (no `'use client'` unless needed)
- Only `ContactForm.tsx` (Phase 2) will need `'use client'`
- Nav hamburger menu toggle needs `'use client'` — extract to a small client sub-component OR use CSS-only approach

**Color Mapping (DESIGN.md → Tailwind):**
```
bg: #fafaf9 → stone-50 (close enough) OR custom 'bg' token
bg-card: #ffffff → white
bg-dark: #18181b → zinc-900
bg-dark-card: #27272a → zinc-800
text-primary: #18181b → zinc-900
text-secondary: #52525b → zinc-600
text-muted: #a1a1aa → zinc-400
accent: #10b981 → emerald-500
accent-muted: #059669 → emerald-600
```
NOTE: Use Tailwind's built-in Zinc + Emerald scales where they match exactly. Only add custom tokens for values that don't map (accent-bg, accent-border, shadows).

**Layout Pattern:**
- `max-w-[1400px] mx-auto` for content containment (from wireframe)
- Left-aligned by default (DESIGN.md anti-slop rule)
- Asymmetric grids, never 3-col equal

## NOTES

### Design Decisions

1. **CSS-only mobile nav**: The wireframe simply hides nav links on mobile (640px). No hamburger menu needed for v1 — the CTA button is always visible. If a hamburger is desired later, extract a small `MobileMenuButton` client component rather than making the entire Nav a client component.

2. **Tailwind built-in Zinc/Emerald vs custom tokens**: We use Tailwind's built-in `zinc-900`, `zinc-600`, `zinc-400`, `emerald-500`, `emerald-600`, `stone-50` which map exactly to DESIGN.md values. Custom tokens only for accent-bg, accent-border (rgba values), shadows, radius, and timing.

3. **`font-outfit` via CSS variable**: Using `next/font`'s variable mode (`--font-outfit`) allows Tailwind to reference the font via `fontFamily: { outfit: ['var(--font-outfit)'] }`. The font className goes on `<html>`, and `font-outfit` utility goes on `<body>`.

4. **No `'use client'` in Phase 1**: Both Nav and Footer are pure Server Components. Zero client JS. This keeps the initial bundle minimal and aligns with the architecture decision in `implementation-plan.md` line 45.

5. **`duration-400`**: Wireframe uses `0.4s` transitions everywhere. Tailwind v3 doesn't have `duration-400` out of the box, so we extend the theme. This is referenced frequently in hover states.

### Risks

- **create-next-app in non-empty directory**: The project root has existing files. The command should handle this, but if it fails, manually init or use a temp directory and move files.
- **Tailwind v3 vs v4**: As of early 2026, create-next-app may ship Tailwind v4 which has a different config format (CSS-based, no tailwind.config.ts). If v4 is installed, adapt the config approach — put theme tokens in the CSS file using `@theme` directive instead. Check `node_modules/tailwindcss/package.json` version after install.
- **`@vercel/analytics` import path**: For App Router, import from `@vercel/analytics/next`. The `/react` path is for Pages Router.
